# 提案：file-backed-multi-doc-editing

## Why

当前 demo 的文档只存在于内存（`initialBlockTexts` 写死在 `main.dart`），重启即失，与真实使用场景（打开文件 → 编辑 → 保存 → 切换文档）脱节。趁业务代码尚未膨胀，先把编辑体验落到真实文件语义上：真实读写、持久化、多文档管理，避免后续功能在「内存态假设」上越积越多。

## What Changes

- **真实文件读写**：文档持久化到应用数据目录（`path_provider` 的应用文档目录），启动时从磁盘载入，保存时写回磁盘。
- **固定文档集**：3 个固定文件（固定文件名），任一不存在（首次启动或被删除）则自动创建并写入各自的初始模板。
- **默认打开**：应用启动默认打开主文档 `welcome.md`，其初始模板覆盖全部已支持 Markdown 特性：标题、列表、任务勾选、表格、引用、围栏代码块、行内/块级数学公式、高亮、图片、图表（chart 块）、目录列表、链接、分隔线。
- **保存**：手动保存（Ctrl+S / 保存按钮），未保存修改以脏标记呈现。
- **文档切换**：左侧抽屉文档列表（当前文档高亮、脏标记），切换到目标文档。
- **未保存语义**：切换文档时若有未保存修改，弹「保存并切换 / 放弃修改并切换 / 取消」三选对话框。
- **块模型扩展（结构块）**：表格、代码围栏、引用、列表等多行结构在载入时归并为单个多行块；`Enter` 在多行结构块内插入换行而非拆块；保存时块间以空行连接回写，保证往返（载入→不改→保存）内容稳定。
- **图表扩展（chart 块）**：经现行 `blockComponents` 扩展 API 注册 ```` ```chart ```` 围栏组件，用 fl_chart 渲染真实图表（模板中含折线图示例）。
- **本地图片渲染**：经现行 `imageBuilder` 让图片语法支持本地文件路径（相对数据目录），模板图片为应用内置资源、首次启动复制到数据目录后按本地文件渲染。
- **明确不做（本轮非目标）**：另存为、新建文档、删除/重命名文档、自定义路径打开、web 平台的文件 IO（web 无真实文件系统，本提案文件语义仅覆盖移动/桌面平台）。

## Capabilities

### New Capabilities

- `document-files`：文档的文件化存储与多文档工作区——固定文档集与自动创建、启动默认打开、载入分块、手动保存与脏状态、抽屉切换、未保存切换语义。

### Modified Capabilities

- `live-preview-editing`：块模型从「单段纯文本」扩展为「可含换行的结构块」；「块编辑操作」中 `Enter` 的行为按块类型区分（普通段落拆块、多行结构块内插入换行）；新增「文件载入分块」「保存回写」对块模型的要求。

## Impact

- **代码**：`flutter_app/lib/main.dart`（应用壳与抽屉导航）；`lib/editor/`（块模型、MarkdownEditor 载入/回写与 Enter 行为、渲染态 chart 块与本地图片）；新增 `lib/document/`（存储层、固定文档定义、模板内容、文档状态）。
- **依赖**：新增 `path_provider`、`fl_chart`；`gpt_markdown` 维持 1.3.0 现行 API（`blockComponents` / `imageBuilder`），不触碰 deprecated 面。
- **平台**：文件语义覆盖 Android / iOS / macOS / Windows / Linux；web 非目标（web 无真实文件系统，保持可编译运行，存储降级为内存实现，重启即失，详见 design）。
- **规格**：`live-preview-editing` 的「块编辑操作」Requirement 被修改（结构块内 Enter 语义）；不影响已实现的行内样式化、预填充补全、双态切换等其余 Requirement。
