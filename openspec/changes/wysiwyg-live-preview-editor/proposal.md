## Why

产品要做的是 Typora 式「输入即渲染」的 Markdown 编辑器：语法标记在输入过程中实时呈现最终样式，对称标记由编辑器自动预填充补全，而不是传统的「源码区 + 预览区」双栏分离形态。当前 `flutter_app/` 还是空骨架，这个输入体验是产品从零到一的核心能力，需要先把目标行为定义清楚，作为后续规格与设计的基准。

## What Changes

- 新增编辑器核心交互「行内语法实时渲染」，以用户给出的基准场景为准（输入 `今天的**天气是晴天**，还不错`）：
  1. 输入 `**` 时，编辑器识别到这可能是一个需要对称闭合的标记，在光标后方显示两个**字体偏虚偏浅**的 `**` 预填充提示（非真实输入内容）；
  2. 输入到 `今天的**天气是` 时，实际显示为 `今天的**天气是|**`（`|` 为闪烁光标），`|` 后的 `**` 是编辑器预填充提示；
  3. 存在预填充提示时按 **Tab** 键完成自动填充，提示文本转为真实输入；
  4. 光标位于未闭合标记内时（如 `今天的**天气是|`），`**` 标记及其包裹的文字以**加粗样式**实时显示——标记字符本身可见，但已呈现目标样式。
  5. 光标离开该标记所在块（如移至其它段落）后，该块切换为渲染态：标记字符隐藏，仅保留样式效果——`**天气是**` 呈现为粗体的「天气是」。
- 同类交互覆盖其它行内/对称语法：斜体、高亮、删除线、行内代码等（语法集合待定）。
- 标题等块级语法同样期望「输入即见样式」的实时渲染效果（具体形态待设计阶段确定）。
- 已定决策：编辑器采用**形态 B——块级架构 + 双态切换**（Typora 形态）。文档由块列表构成，块间可导航；光标所在块为编辑态（上述基准场景，标记可见且样式化），光标离开后该块为渲染态（标记隐藏、仅保留样式）。
- 已定决策：语法集合纳入**高亮**（`==…==` 扩展语法）与**公式**（LaTeX，行内 `\(…\)` 形式）。

## Capabilities

### New Capabilities

- `live-preview-editing`: 编辑器的实时渲染能力——行内标记的即时样式化、对称标记的预填充提示与 Tab 补全、进行中（未闭合）标记的实时样式反馈、块级语法的实时样式，以及块的编辑态/渲染态双态切换。

### Modified Capabilities

（无——项目尚无已归档规格）

## Impact

- **代码**：`flutter_app/` 全部为新增代码；编辑器输入面（编辑控制器、实时样式管线）为核心新模块。
- **依赖**：编辑面（编辑态）的实时渲染需要自建管线（定制 `TextEditingController.buildTextSpan` + 按键拦截），无现成渲染包可直接承担。
  已评估 gpt_markdown (1.3.0)：定位为 AI 输出的纯渲染库，无法承担编辑面实时渲染；
  形态 B 下可作为渲染态整块渲染的候选之一（使用时须遵守项目规则：禁用其全部 `@Deprecated` API），最终选型在 design 阶段定稿。
- **后续**：本提案确立目标行为；语法可见性策略与语法集合定稿后，再产出 specs / design / tasks。
